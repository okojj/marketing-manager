# 콘텐츠 스튜디오

## 사용 흐름

1. 로그인 후 브랜드 카드의 **아이디어 · 콘텐츠 만들기**를 선택합니다.
2. 주제, 목표, 키워드, 방향과 제작할 채널을 입력합니다.
3. **AI 아이디어 3개 제안받기**를 누릅니다. 아이디어와 입력 내용은 DB에 저장됩니다.
4. 원하는 아이디어에서 **이 아이디어로 캠페인 만들기**를 누릅니다. 직접 작성한 기획을 캠페인으로 저장할 수도 있습니다.
5. 캠페인에서 **채널별 초안 생성**을 누릅니다. 블로그, Instagram, LinkedIn 중 선택한 채널마다 한 편씩 생성됩니다.
6. **수정 및 이력 보기**에서 제목과 본문을 수정합니다. 저장할 때마다 새 버전이 추가됩니다. **복사**로 외부 편집기에 가져갈 수 있습니다.

이 단계에서는 텍스트 초안을 생성합니다. 이미지 제작, 대화형 AI 수정, 승인, 실제 게시, 예약 발행은 포함하지 않습니다. Instagram 게시에는 추후 이미지와 게시 권한 연동이 필요합니다.

## Ollama 설정

Ollama 앱을 실행한 뒤 `ollama list`에 표시된 모델 이름을 사용합니다. 모델은 자동 다운로드하지 않습니다.

```dotenv
AI_PROVIDER=ollama
OLLAMA_MODEL=gemma4:latest
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_DOCKER_BASE_URL=http://host.docker.internal:11434
OLLAMA_TIMEOUT_SECONDS=240
```

`./run.sh local`은 OLLAMA_BASE_URL을, `./run.sh dev`의 백엔드는 OLLAMA_DOCKER_BASE_URL을 사용합니다. Docker Desktop에서 Mac 호스트의 Ollama에 연결하며 컨테이너는 기존 3개를 유지합니다. 원격/Linux 환경은 컨테이너에서 접근 가능한 Ollama 주소로 OLLAMA_DOCKER_BASE_URL을 설정하세요.

현재 로컬에 설치된 다른 모델은 `OLLAMA_MODEL=llama3:latest`로 선택할 수 있습니다. 변경 후 로컬 백엔드를 재시작하거나 `./run.sh dev`를 실행하세요. 화면에는 현재 공급자와 모델이 표시됩니다. API 키는 필요하지 않습니다. 모델의 JSON 구조화 출력과 한국어 품질에 따라 생성 성공률이 달라질 수 있으며 첫 호출은 모델 로딩 때문에 오래 걸릴 수 있습니다. 연결 실패·모델 없음·시간 초과는 별도 오류로 안내합니다.

## OpenAI 설정

프로젝트 루트 `.env`에 다음 항목을 설정합니다. 기존 Google OAuth와 APP_ORIGIN 값은 유지하세요.

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=서버에서만_사용할_API_키
OPENAI_MODEL=gpt-4.1-mini
AI_DAILY_LIMIT=30
```

```bash
./run.sh dev
```

로컬 모드는 백엔드를 재시작합니다. API 키가 없으면 AI 생성 버튼은 비활성화되지만 기존 콘텐츠 열람·수정과 직접 캠페인 저장은 가능합니다. 실제 서버에는 테스트 응답이나 인증 우회를 넣지 않았습니다.

OpenAI와 Ollama를 지원합니다. `AIProvider` 인터페이스와 `get_provider()`를 통해 다른 공급자를 추가할 수 있습니다. 모델은 Responses API와 strict JSON schema 출력을 지원해야 합니다. API 키는 브라우저나 API 응답에 노출하지 않으며 Google 로그인 정보와 분리합니다.

## 데이터와 동작

- `ai_generations`: 사용자·브랜드·요청 식별자, 요청 컨텍스트, 결과 또는 오류, 모델, 토큰 사용량.
- `campaigns`: 목표, 키워드, 채널, 기획, 생성 당시 브랜드 정보 스냅샷.
- `contents`: 채널별 최신 초안.
- `content_revisions`: AI 최초 초안 및 모든 수동 수정본.
- 사용자 소유 브랜드를 통해 캠페인·콘텐츠 접근 권한을 검사합니다.
- 생성된 아이디어 한 개를 여러 번 눌러도 같은 캠페인을 반환합니다.
- 초안이 있는 캠페인의 생성 요청은 기존 초안을 반환하므로 수동 수정본을 덮어쓰지 않습니다.
- 수정 시 버전이 다르면 409를 반환합니다. 편집 내용을 별도로 보관한 뒤 편집기를 닫고 저장 내역을 새로고침하세요.
- 아이디어나 캠페인이 연결된 브랜드는 삭제를 차단합니다. 작업 이력을 실수로 지우지 않도록 한 현재 정책이며 보관·삭제 정책은 추후 확장합니다.
- 최신 아이디어 생성 이력 50건을 화면에 표시합니다. 이전 이력은 DB에 보존됩니다.

## AI 요청 처리

브랜드 설명, 타깃, 톤과 사용자가 입력한 기획을 선택한 공급자에 전달합니다. Ollama 선택 시 설정된 Ollama 서버에서 추론합니다. Google 계정의 이름·이메일·로그인 토큰은 전달하지 않습니다. OpenAI 선택 시 Responses API의 `store=false`를 사용합니다. 서비스 DB에는 재접속과 수정 이력을 위해 입력과 결과를 저장합니다.

공식 structured output 형식을 사용한 뒤 서버에서 필수 필드, 3개 아이디어, 선택 채널의 정확한 일치, 문자열 길이를 다시 검증합니다. AI 프롬프트에는 제공되지 않은 가격·할인·통계·기능을 만들지 않도록 지시합니다. 이는 사실 정확성을 보장하지 않으므로 사용자가 초안을 검토해야 합니다.

- 사용자별 최근 24시간 생성 시도 제한(기본 30회, 실패한 공급자 호출 포함).
- MySQL 사용자 행 잠금으로 동시에 하나의 생성 요청만 실행. 중복 대기는 409 응답.
- 같은 요청 식별자와 입력으로 재시도하면 저장된 결과 재사용.
- 자동 유료 재시도 없음. 공급자 시간 초과/한도/거절/잘못된 응답을 사용자 메시지로 반환.
- 연결 시간 제한 5초, OpenAI HTTP 요청 I/O 제한 40초, Ollama 기본 240초, 프런트 프록시 제한 300초. 외부 리버스 프록시를 사용하면 해당 응답 제한도 300초 이상으로 설정하세요.
- 생성 결과와 모든 채널의 최초 수정 이력은 한 트랜잭션으로 저장.

현재는 단일 동기 생성 흐름입니다. 공급자가 응답한 직후 서버나 DB가 중단되어 결과가 저장되지 않은 경우 재시도 시 외부 호출이 중복될 수 있습니다. 규모 확장 시 작업 큐, 영구 실행 상태와 공급자 요청 추적을 추가하세요. 생성 중에는 해당 사용자의 DB 행 잠금과 연결을 유지합니다.

## 검증

```bash
cd backend
../.venv/bin/python -m pytest -q
# 프로젝트 루트에서
npm --prefix frontend run typecheck
docker compose exec -T backend alembic check
```

로그인 회귀 검증을 포함한 자동 테스트 31개가 통과했습니다. 공급자 오류 처리는 테스트용 HTTP 응답으로 검증했습니다. Docker 백엔드에서 Mac의 실제 gemma4:latest로 아이디어 3개(약 46초)와 Instagram 초안 1개(약 25초)를 생성하고 구조를 검증했습니다. 실제 OpenAI API 호출은 키가 없어 미검증입니다. 브라우저에서는 실제 계정과 분리한 임시 DB·테스트 응답으로 아이디어 → 캠페인 → 3채널 초안 → 수정본 v2 → 새로고침 → 이력 조회 흐름을 확인했습니다.

참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
