# AI Marketing Manager 기획

## 목적
브랜드 정보를 바탕으로 아이디어 발굴 → 캠페인 기획 → 채널별 콘텐츠 생성 → 사용자 검토·수정 → 승인 → 게시를 지원하는 마케팅 작업 공간.

## 핵심 사용자 흐름
1. 브랜드명, 서비스 설명, 타깃, 브랜드 톤, 목표를 등록한다.
2. 주제·키워드·방향성을 입력하고 홍보 아이디어를 제안받는다.
3. 아이디어를 캠페인으로 구성하고 블로그·Instagram·LinkedIn별 콘텐츠를 생성한다.
4. 대화와 직접 편집으로 초안을 다듬고 버전을 보존한다.
5. 사용자가 최종 승인한 버전에 대해서만 게시 또는 내보내기를 실행한다.
6. 설정에서 채널 OAuth/API 인증과 연결 상태를 관리한다.

## 구현 순서
- **Phase 1 기반 (이번 작업):** Next.js/TypeScript, FastAPI, MySQL, SQLAlchemy/Alembic, health API, 초기 화면, local/dev 실행 구성.
- **Phase 1 기능:** 브랜드 CRUD → AIProvider 인터페이스 및 실제 공급자 연결 → 아이디어/캠페인 → 채널별 콘텐츠·수정 이력 → 승인 상태 관리 → 지원 가능한 채널 게시.
- **Phase 2:** 예약 게시, 재시도·중복 방지, 채널 인증 갱신, 캘린더.
- **Phase 3:** 성과 수집, 다음 콘텐츠 제안, 브랜드 지식 검색.

## 데이터 모델 방향
현재 `brands`, `users`, `login_sessions` 테이블이 구현되어 있다. Google 로그인과 사용자별 브랜드 CRUD까지 구현했다. `ai_generations`, `campaigns`, `contents`, `content_revisions`를 추가하여 아이디어·캠페인·초안과 수동 수정 이력을 구현했다. 다음은 대화형 AI 수정과 승인 상태, channel_connections, publish_jobs 순서다. 발행 이력은 승인한 콘텐츠 버전과 연결한다.

## 설계 원칙
- 브라우저는 동일 출처 `/api`를 호출하고 Next.js가 FastAPI로 전달한다.
- DB 모델 변경은 Alembic 마이그레이션으로 관리한다.
- AI 공급자 교체가 가능하도록 공급자 호출과 업무 로직을 분리한다.
- 외부 콘텐츠 게시에는 사용자 승인과 재시도 시 중복 방지 설계가 필요하다.
- 채널별 공식 API의 권한·지원 범위를 연동 시점에 확인한다. API가 없는 채널은 내보내기 흐름부터 제공한다.
- 인증 토큰과 AI 키는 서버에서 관리하고 클라이언트 번들에 포함하지 않는다.

## 기반 완료 기준
local 모드의 두 hot reload 서버 실행, dev 모드의 세 컨테이너 정상 상태, MySQL 연결 및 최초 마이그레이션, 초기 화면과 health proxy 응답을 확인한다.
